# Shape Architects Render Deploy Checklist

This repo is production-prepared for a Render Blueprint deploy.

## Services Created By `render.yaml`

- `shape-architects-crm-db` - PostgreSQL
- `shape-architects-crm-api` - Express API, Prisma, file uploads on Render Disk
- `shape-architects-crm-web` - CRM static app
- `shape-architects-landing` - public landing + `/admin`

## Public URLs

- CRM: `https://shape-architects-crm-web.onrender.com/`
- Landing: `https://shape-architects-landing.onrender.com/`
- Landing admin: `https://shape-architects-landing.onrender.com/admin`
- API health: `https://shape-architects-crm-api.onrender.com/health`

## Demo Credentials

- CRM admin: `admin@shape.local` / `shape-admin-2026`
- Landing admin: `shape-admin-2026`

Change these after client review.

## Required Render Flow

1. Push this folder to a GitHub repository.
2. In Render, create a new Blueprint from that repository.
3. Render reads `render.yaml` and creates all services.
4. Wait for API deploy first, then static sites.
5. Open `/health`.
6. Open CRM and login.
7. Open landing admin and edit/save a small text.
8. Submit landing contact form and confirm client appears in CRM.

## Env Notes

- `DATABASE_URL` is injected from Render PostgreSQL via `fromDatabase`.
- `AUTH_SECRET` is generated by Render.
- `STORAGE_DIR=/var/data/uploads` uses the Render Disk attached to the API.
- `VITE_API_URL` is set for CRM and landing static builds.
- Gmail, mail sync, campaigns, and AI summaries need real provider keys before they fully work.

## Local Note

The production schema uses PostgreSQL. For local development after this change, use a local PostgreSQL URL in `apps/server/.env` instead of SQLite.
